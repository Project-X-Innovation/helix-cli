## Title
A theory of tests and documentation for Helix Customers

## Description
Helix Customers will be using Helix to implement their business logic and systems.



Ultimately Helixs job will be to implement the business Bible and make sure it is running by monitoring and showing examples 



However, in the old world, devs built tests and customer facing documentation for their systems. Tests to ensure no regressions, documentation to let the users know how to build the features 



So two themes that need digging into. How do these two concepts evolve when we have a business Bible and live monitoring 

Do we and if so, how do we implement these in a canonical way in Helix
